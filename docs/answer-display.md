# 回答的显示：Markdown 正文和互动卡片

> 2026-10-19 写定。提问页和详情右栏已按这份显示。
> `docs/swiftui-redesign.md` 第 18 节里「回答和摘要只用标题、列表、粗体。流式输出时按纯文本显示，结束后再解析成这几种块来画，不用 WebView」这一句作废，以这份为准。流式吐字本身已经在 `parallel` 上，这份只管字回来之后怎么画。

提问页和会议详情里的回答分成两路。讲清楚事情的文字用 Markdown，由应用自己画。需要动手试一下才能看懂的那一小块，用系统自带的 WKWebView 画成一张互动卡片。参考的是 Gemini 那种回答：解释是正文，旁边可以有一个能拖、能点的小图。Nomi 用 macOS 自带的 WebKit，不另带浏览器内核。

互动卡片是回答的一部分，帮用户理解刚才那段话。它不能替用户查会议、改笔记、打开网页，也不能当工具去跑命令。

## 1. 为什么分成两路

一场课的回答主要是句子、要点、术语和时间。这些要能选中、复制、被辅助功能读出来，也要在字还在往外冒的时候就能看。用应用自己的文字来画最合适。

有些内容字排出来仍然不好懂。例如一条曲线跟着一个数变化、两种分法并排对比、一个定义配一个可以拨动的例子。这种块让用户自己改一个数、马上看到结果，比再写一段解释更容易懂。它是一小张自己的页面，Markdown 表达不了。

两路分开，正文就不会变成一张网页，卡片也碰不到会议、钥匙串和磁盘。

## 2. 用户看到什么

一条回答从上到下是普通文字，中间可以夹零到两张卡片。卡片和文字一样宽，左边对齐，最宽 680 pt，圆角和回答里的其他块一致。卡片没有地址栏，也没有另一层窗口。

卡片里是模型写的那一个小交互：滑块、开关、按钮、一张用图形画出来的图。用户拨动它，只改变这张卡片里面的样子。松手之后，上面和下面的文字不变。

卡片可以有一行小标题，用模型在标记里写的名字，例如「拖动看斜率」。没有名字就用「互动图示」。

重新打开这条回答时，卡片回到一开始的样子。拨过的位置不保存。

提问页和详情右栏的提问、摘要用同一套。摘要里如果出现这种卡片，也照样放进正文中间。

## 3. 模型怎么写

模型仍然输出一整段 Markdown。普通段落、标题、列表就是正文。只有它认为「动手试一下更容易懂」的时候，才单独加一块语言标记为 `html` 的围栏。围栏外面的尖括号一律当成文字，不会变成卡片。

一块卡片长这样：

````
```html 拖动看斜率
<svg>...</svg>
<input type="range">
<script>...</script>
```
````

围栏第一行 `html` 后面的文字是卡片标题，可以空着。围栏里可以是一段片段，也可以是带 `html`、`head`、`body` 的完整页面。应用会丢掉文档壳、字符集和视口声明，只留下样式、页内脚本和正文，再补上约束和量高度的外壳。围栏没有语言标记、但正文明显是一整页 HTML 时，也按同一规则处理。`python` 这类别的语言标记仍然只当代码。

同一条回答最多两块。再多的 `html` 围栏不执行，收成普通代码块，让用户仍能看见模型写了什么。一块超过 24 KB 同样收成代码块。

其他语言的围栏，例如 `python`、`swift`，是代码，用等宽字显示，可以选中复制。它们不进 WebView，应用也不运行它们。

## 4. Markdown 正文

正文由应用解析后用自己的文字样式画，不放进 WebView。支持这些：

- 段落、换行
- 标题（最多三级）
- 粗体、斜体
- 有序列表和无序列表
- 行内代码，以及非 `html` 的代码块
- 简单表格
- http 和 https 链接。点了用系统浏览器打开。别的链接方案不打开

已经有的引用保持原样：回答里的 `[mm:ss]` 仍是时间胶囊，点了跳到对应段落；资料和网页引用仍是回答下面的胶囊。解析 Markdown 时不要把这些胶囊吞掉。

正文里出现的 HTML 标签显示成文字，不解释成页面。这样模型随口写的 `<div>` 不会变成第二张不受约束的页面。

流式输出过程中，已经确定的正文先按纯文字显示。这条回答结束后，再解析成上面这些块。解析失败的那一段退回纯文字，整条回答不因此空白。

## 5. 互动卡片

围栏闭合、并且通过第 6 节的检查之后，应用才创建 WKWebView。没闭合的围栏不创建页面，避免脚本只跑到一半。

应用加载的是自己拼好的一页，不是模型给的原文字符串：

- 页头写上内容安全策略：默认不许加载任何外部资源；样式和脚本只能是写在这一页里的；不许图片地址、不许再嵌页面、不许发起连接。
- 把界面当前的文字色、底色、强调色写成这一页的 CSS 变量，卡片默认跟上系统的浅色或深色。
- 模型的片段放在页面主体里。
- 外壳用页面自身的高度变化来通知应用，模型不必专门调用应用。

卡片里允许的是一块自包含的说明图：文字、按钮、滑块、勾选、数字输入、表格、内联 SVG、画布，以及写在页内的样式和脚本。脚本只能改这一页自己的内容。

字符集、视口和标题这三种页面声明会在拆页时丢掉，不因此退回代码块。别的 `meta`（例如自动跳转）一旦出现，整块不进 WebView。下面这些标记或属性也一样，整块按第 3 节收成代码块：

- 再嵌套的页面、外部脚本、外部样式、会跳转的基址
- 会提交到某处的表单
- 图片、音视频。图用内联 SVG 或画布画。不从网络或磁盘取图
- 文件选择、密码框
- `javascript:` 链接，以及任何会离开这一页的地址

脚本报错时，应用不退出。这一页已经画出来的部分留着，外面的 Markdown 不受影响。

## 6. 页面怎么被关起来

模型写的 HTML 按不受信任的内容处理，即使用户自己问出来的也一样。WKWebView 用下面这些边界：

- 用系统 WebKit。不内置、不下载别的浏览器内核。
- 数据存在这块 WebView 自己的内存里，关掉回答或离开页面就丢掉。不写磁盘，不留 cookie。
- 不访问文件、钥匙串、麦克风、会议记录、资料库。
- 不联网。卡片不能自己去拉页面、字体、图片或数据。
- 不能开新窗口，也不能把当前这页导航到别的地址。任何跳转都取消。
- 应用和这页之间只留一个口，名字叫 `nomi`。这一页只能通过它报告高度，格式是一个数字字段 `height`。别的消息丢掉。
- 这个口不能查会议、不能读密钥、不能让应用执行命令，也不能把卡片里的字发到别处。

调试版本可以检查这张卡片里的页面，方便看脚本为什么没跑。正式打包的应用关掉这项。

## 7. 高度

外壳在页面尺寸变化时把高度发给应用，包括第一次出现，以及用户拨动滑块后内容变高的时候。应用把 WebView 设成这个高度。

高度限制在 44 pt 到 480 pt。低于 44 时用 44，避免一条线看起来像加载失败。高于 480 时卡片内部滚动，回答本身不被一张图撑满。

500 毫秒内没有收到高度，就用 160 pt，之后如果高度到了再改。用户不会看到一张无限高的空白。

## 8. 流式输出时怎么显示

字仍是边生成边出现。显示规则：

- 围栏以外的字，按纯文字往下接。
- 一旦出现未闭合的 `html` 围栏，里面的源码先不铺开，这一位置显示一行「正在准备图示…」。
- 围栏闭合后，生成还没结束时，这一位置仍是那一行占位。等整条回答结束，检查通过才换成卡片，正文再解析成 Markdown。
- 检查没通过，占位换成普通代码块，不弹错误窗。
- 思考过程仍不展示。只有正文和通过检查的卡片给用户看。

停止生成时，已经出现的文字按现有规则处理：提问页停了，问题回到输入框，不保留半段回答。因此停掉的回答也不会留下一张半成品卡片。

## 9. 存下来和复制

存的是模型输出的 Markdown 原文，包含 `html` 围栏。不存截图，也不把卡片另存成文件。下次打开，用原文再走一遍第 4 节和第 5 节。

复制这条回答时，复制存下来的 Markdown。卡片不是一段可以单独复制的纯文字。用户要看源码，可以从收成代码块的失败卡片里复制；通过检查的卡片不额外提供「查看源码」，避免和正文复制混在一起。

## 10. 提示词

在现有提问和摘要的系统提示后面加一句，中英文界面都用模型语言：

> 用 Markdown 写回答。只有当一个小交互能帮用户理解时，才加一块语言为 html 的围栏。围栏里写片段或完整页面都可以，用滑块、按钮、内联样式、内联脚本和内联 SVG。不要引用外部地址，一条回答最多两块。

本机小模型经常写不出合格片段。写坏了就按第 3 节退回代码块，正文仍然在。不因为本机模型不擅长 HTML 就关掉 Markdown。

## 11. 不做

- 不把整条回答放进一个网页里显示。
- 不内置 Chrome 或其他内核。
- 不做工具调用、MCP、A2UI。卡片不能向应用要数据，也不能改会议。
- 不在应用里执行模型给出的命令或代码。终端输出、命令示例只作为代码块。
- 不上传图片，也不显示网络图片。图只画在卡片内部。
- 不让用户把自己的 HTML 文件拖进回答里运行。只有这条回答里的围栏会进 WebView。
- 不在卡片里打开资料、PDF 或会议转写。那些仍用现在的默认应用和时间胶囊。
- 不保存滑块位置，不做跨回答共享的页面存储。

## 12. 验收

设计落地时用这几条判断，先不必做新的自动界面操作：

- 一段只有标题、列表和粗体的回答，看起来是应用里的文字，中间没有 WebView。时间胶囊仍能点。
- 一段文字中间夹一块合格的 `html` 围栏时，文字是 Markdown，中间是一张可拖动的卡片，拖动时文字不重排、应用不发网络请求。
- 围栏里写了外部脚本、外链图片或嵌套页面时，这块变成代码块，前后文字照常显示。
- 生成过程中能看到字逐渐出现；没写完的 `html` 围栏处是「正在准备图示…」，结束后才变成卡片或代码块。
- 离开再打开同一条回答，卡片还在，并且回到初始状态。
- 提问页和详情右栏的摘要、提问用同一种块。
