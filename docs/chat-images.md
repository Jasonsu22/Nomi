# 对话里的图片

> 2026-10-19 写定。提问页和会议详情右栏按这份做。

现在的对话只能显示文字。问题是一段字符串，回答是 Markdown。模型请求里的 `content` 也是一整段字符串。回答里的 HTML 卡片明确禁止 `<img>`，内容安全策略里的 `img-src` 是 `none`。所以截图、粘贴的图片、回答里的图片地址，现在都出不来。

这份只做静态图片。视频、模型自己画图的接口、以及让本地 MLX 引擎看图，都不在这一版。

## 1. 模型能不能看图

看图和展示图片是两件事。图片先要能在对话里画出来。要不要把像素发给模型，取决于当前选中的模型。

| 模型 | 模型本身 | 应用现在 |
| --- | --- | --- |
| MiniMax-M3、MiniMax-M3.1-Flash | 能看图。官方 OpenAI 兼容接口用 `image_url`，Anthropic 兼容接口用 `image` 块。格式是 JPEG、PNG、GIF、WEBP，单张不超过 10 MB，整个请求体不超过 64 MB。 | 只发纯文字，所以现在它看不到用户贴上的图。 |
| MiniMax M2 系列 | 官方写明只收文字和工具调用，不收图片。 | 同样只发文字。 |
| 本地 Qwen3、Qwen3.5 | Qwen3.5 2B 的权重是图文模型，本来可以用 mlx-vlm 看图。目录里的 Qwen3 0.6B / 4B 是纯文字。 | 本地引擎只收 `system`、`prompt` 和 `max_tokens`。这一版不改 Rust，也不改 MLX。本地模型看不到图。 |
| 自定义 OpenAI 兼容接口，例如现在的 codex 配置 | 看对方的模型。标准做法是把 `content` 写成文字块加 `image_url` 块。 | 现在只发字符串。做完之后按标准格式发；对方不认图片时，把接口返回的错误显示在这条回答上。 |

结论：展示、放大、复制、保存，不依赖模型。把图片放进输入框并发给能看图的远程模型，是同一版要做的。本地模型这一版只把图片留在对话里，不把像素送进引擎。

## 2. 用户看到什么

图片出现在三个地方，外观一致：输入框里待发送的缩略图、发出之后问题气泡里的缩略图、回答正文里的图片。

待发送和已发出的缩略图都是同样大小的圆角正方形，边长 48 pt，多出来的部分裁掉，排成一行。输入框里，这一行紧贴在文字正上方。发出去之后，同样的一排在问题文字正上方，靠右，不再放大到整张。回答正文里的图片仍按原比例，最宽 680 pt。

点开时，暗底和图片从同一下开始，一次性放大到全屏并淡入，不会先整张出现再补一次放大。关闭按同一条动画收回。系统打开了「减少动态效果」时不做这个动画。点任何一张已经显示出来的图片，画面盖上一层半透明暗底，图片在正中按窗口大小放大，四周留 48 pt。暗底盖住整个窗口，包括侧栏。右上角有一个圆形关闭按钮，图标是 `xmark`，辅助功能名称是「关闭」。按 Esc，或点暗底上图片以外的地方，也关闭。放大时不能滚动底下的对话。放大后的图片上右键，菜单和缩略图相同。

右键菜单只有两项：

- 拷贝图片
- 将图片存储为…

拷贝把图片放进系统剪贴板，文字编辑器里粘贴得到图片，不是路径。存储为打开系统保存面板，默认文件名用原来的名字；没有名字时用 `image.png`。用户取消保存就什么都不做。

右键时不打开放大。放大和右键互不触发。

## 3. 输入框

输入框圆角区域里面，文字上面多一行附件。没有图片时这一行不占高度。

放进输入框的办法：

- 直接粘贴，用 ⌘V。剪贴板里是 JPEG、PNG、GIF、WEBP、HEIC、TIFF，或一张图片文件时，粘贴进输入框变成缩略图，不把二进制塞进文字。剪贴板里是文字时，仍按现在的方式贴进文字。
- 把图片文件拖进输入框。
- 点输入框左侧的曲别针，用系统文件面板选图片。可以多选。

鼠标停在某一张待发送的缩略图上时，右上角才出现一个小圆按钮，里面是 `xmark`。点它只移走这一张，文字和其他图片留着。发出去之后的缩略图没有这个叉。文字为空时按删除键，移走最后一张图片。

一张图都没有时，发送按钮仍要求文字不是空白。有图片时，文字可以是空的，也能发送。发送后输入框里的文字和图片一起清空。生成过程中按停止，文字和还没发出的图片都回到输入框。

一次最多 8 张。超过的不再加入，输入框下出现一行说明：「一次最多 8 张图片。」格式只收 JPEG、PNG、GIF、WEBP、HEIC，以及 macOS 截图粘贴出来的 TIFF。HEIC 和 TIFF 在加入时转成 PNG 再保存。其他文件跳过，并说明「只能加入图片。」单张原文件超过 10 MB 时不加入，说明「单张图片不能超过 10 MB。」

读不出来的文件不显示裂图占位，直接跳过并说明「这张图片无法读取。」

会议详情右栏的输入框用同一套。

## 4. 发出之后

问题气泡里，图片在文字上面，右对齐，和气泡同一侧。只有图片、没有文字时，气泡里只显示图片。图片可以点开、可以右键拷贝和存储。

回答里的 Markdown 图片单独成块，不塞进句子中间。模型写成 `![说明](地址)` 时，说明文字在图片下面，用辅助说明的字号。地址必须是 `https`。`http`、`file`、`javascript` 和其他方案只显示成普通链接文字，不去下载。

代码块里的图片地址保持代码，不显示成图。HTML 卡片继续禁止外部图片，这一版不改那条安全规则。

远程图片先显示一块和正文同宽、高度 120 pt 的浅底，加载完成后换成图片。失败时这块留下，里面写图片的说明文字；没有说明就写「图片无法显示」。不自动重试。

GIF 用系统图片视图播放。放大时也播放。

## 5. 图片存在哪里

对话 JSON 里不写像素，也不写 base64。一条问题增加附件列表，每项是标识、原来的文件名、媒体类型，以及相对路径。旧对话没有这个字段，打开时当成没有图片。

文件放在 `~/Library/Application Support/Nomi/chat-images/` 下面，每个附件一个目录，里面是转好的图片。删除对话时删掉这些目录。只从输入框里叉掉、还没发送的图片放在临时目录，发送成功后挪进上面的位置；关掉应用时清掉没发送的临时文件。

发给模型之前，在内存里把长边缩到 2048 像素，再编成 PNG 或原来的 JPEG。对话里显示和「存储为」用的是保存下来的那一份，不另存一份更小的。缩图只为了请求不要过大。

## 6. 什么时候把图片发给模型

远程、而且当前模型接受图片时，这一轮的用户消息不再是一个字符串，而是一块文字加上若干图片块。

OpenAI 兼容格式里，文字是 `{"type":"text","text":...}`，图片是 `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}`。MiniMax 这一路再加 `"detail":"default"`。

Anthropic 格式里，图片是 `{"type":"image","source":{"type":"base64","media_type":"...","data":"..."}}`。

后面几轮如果用户说「这张图」，模型需要还能看见它。组请求时带上最近 4 轮里的图片，并且这一整次请求最多 8 张；更早的图片只保留「用户发过一张图片」这句话，不再附像素。隐藏的演示子任务仍然只收那段文字说明，不收图片。

本地模型，以及已知不看图的 MiniMax M2 系列：图片照样出现在对话里，请求里不附像素。输入框里已经有图片时，发送按钮旁边不再挡发送，改为在附件行下面写一行：「当前模型看不到图片，图片只会留在对话里。」换到 MiniMax-M3、MiniMax-M3.1-Flash，或一个尚未标明的远程模型时，这行消失，并按上面的格式附上图片。

尚未标明的远程模型按能看图来发。接口拒绝图片时，这条回答显示接口的错误原文，对话里的图片仍然留着。

## 7. 这一版不做

- 不改本地 MLX 引擎，Qwen 在应用里仍然看不到图。
- 不接视频，也不接模型画图接口。
- 不让 HTML 卡片加载外部图片。
- 放大视图里不再做二次缩放、旋转和画廊左右切换。
- 不把图片放进系统提示词，提示词保持现在的文字。
